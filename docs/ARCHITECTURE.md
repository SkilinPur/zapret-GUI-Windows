# Архитектура и план: zapret-GUI-Windows

Дата: 2026-09-10. Статус: проектирование (M0). Linux-версия заморожена как есть;
Windows — отдельный репозиторий `SkilinPur/zapret-GUI-Windows`.

## 1. Общая идея

Переносим **GUI-концепт** (вкладки, мастер, обновление модулей, тёмная тема,
трей) с Linux на Windows. GUI-слой — чистый PySide6, он кроссплатформенный.
Подход — **как в Linux-версии**: GUI не содержит движок, а оборачивает готовый
пакет [Flowseal/zapret-discord-youtube](https://github.com/Flowseal/zapret-discord-youtube)
(релиз-пакет: `.bat`-стратегии + `lists/` + `bin/` с winws.exe и WinDivert).
GUI скачивает/обновляет этот пакет в `engine/` и запускает из него winws —
аналогично тому, как Linux-GUI управляет портом через `service.sh`.

Меняется только «адаптер», вокруг которого строится GUI.

## 2. Стек и внешние зависимости

- Ядро обхода: **winws.exe** — Windows-сборка nfqws из bol-van/zapret
  (или из релиза Flowseal). Опции у winws те же, что у nfqws.
- Перехват: **WinDivert** (`WinDivert64.sys` + `WinDivert.dll`) — драйвер,
  требуется администратор при установке.
- Стратегии: `.bat`-наборы параметров (winws-стиль) + `lists/*.txt` +
  `bin/*.bin` шаблоны. Источник — Flowseal/zapret-discord-youtube (там же
  лежат winws.exe и WinDivert).
- UI: Python 3.11+ + PySide6.
- Сборка: PyInstaller (`--onedir`, потом `.exe`/установщик Inno Setup).

## 3. Что переезжает из Linux-GUI без изменений (по смыслу)

| Блок | Файл (в Linux-GUI) | Примечание |
|---|---|---|
| Главное окно, сайдбар, шапка | `window.py` | платформонезависимо |
| Вкладка «Статус» | `status_tab.py` | бэкенд через интерфейс |
| «Конфигурация» + авто-описание | `config_tab.py`, `zapret.strategy_description` | парсер .bat общий |
| «Обновление» (3 модуля) | `update_tab.py`, `updater.py` | источники поменяются |
| Мастер первого запуска | `wizard.py` | шаги под Windows |
| Справка/Авторство/тема/трей | `help_tab.py`, `theme.py`, `tray.py` | почти без изменений |
| Пояснение GameFilter/термины | — | скопировать тексты |

## 4. Новый бэкенд (Windows)

Один класс-интерфейс `Backend`, у которого методы, которые GUI уже вызывает:

- `state()` → работает/остановлен (winws-процесс жив?), сколько процессов;
- `start(strategy)` / `stop()` — запустить/остановить все winws-процессы;
- `installed_core_version()`, `latest_core()` (обновление winws);
- `strategies_rev()`, `latest_strategies()` (обновление стратегий);
- `set_strategy(name)` — сохранить выбор;
- `autostart_enabled()/enable()/disable()` — планировщик задач;
- `reachable_youtube()/discord()` — самопроверка.

### 4.1 Запуск обхода (аналог `service.sh daemon`)
1. Проверить/поднять WinDivert (запустить драйвер, если нужно).
2. Разобрать выбранный `.bat` → список команд (winws + аргументы), как это
   делал bash-парсер: строки `winws … --filter-tcp=…` разбиваются по `^`.
   Точный формат взять из Flowseal-стратегий (Windows) — там команды уже
   под winws.
3. Запустить по winws-процессу на каждую команду (через `subprocess.Popen`,
   admin). Держать PID-ы; при `stop()` — `taskkill /T`/by pid.

### 4.2 Права (UAC)
- GUI запускается с правами пользователя; действия, требующие админа
  (установка драйвера, запуск winws, планировщик), выполняются через
  **перезапуск себя с `ShellExecute(runas)`** или helper-процесс.
- Упрощение против Linux: не нужен «ввод пароля каждый раз» — один UAC-запрос.
- Вкладка «Права» заменяется информацией «запускать от администратора» +
  кнопкой проверки/авто-elevate. Мастер: шаг прав = подтверждение UAC.

### 4.3 Автозапуск
- Вариант по умолчанию: **пункт планировщика** «при входе пользователя»
  запускает GUI в трее (или winws-демон без окна). GUI всё равно нужен для
  статуса/трея.
- Вкладка «Сервис» → «Автозапуск» (вкл/выкл), статус задачи.

### 4.4 Обновления
- Программа: замена файлов (git pull не годится у пользователя без git;
  вариант — самообновление из релиза-архива GitHub, распаковка поверх себя +
  перезапуск; на время разработки допустимо и через git).
- Ядро winws + стратегии: те же 2 модуля, источники — bol-van/zapret
  (Windows-бинарь в релизе) и Flowseal (git/архив).
- Вкладка «Обновление» = 3 модуля как в Linux.

### 4.5 Стратегии на Windows
- Использовать **нативные Flowseal-стратегии** (имена `general (ALT).bat` и
  т.п., команды под winws), а не переименованные Linux-копии. Хранить/клонить
  из Flowseal в `strategies/`; описания — общим парсером (вытащить из
  `zapret.py: strategy_description` в общий модуль).

## 5. Ограничение среды разработки

Код пишем на Linux (Arch), **winws/WinDivert на Linux не запускаются**.
Поэтому:
- для GUI-части — сборка/импорты проверяем оффскрином, тесты бэкенда через
  **мок-бэкенд** (фейковый `Backend`, те же состояния);
- реальный запуск winws — на стороне пользователя (Windows);
- позже подключить GitHub Actions `windows-latest`: сборка PyInstaller + smoke
  (import + запуск GUI offscreen), чтобы ловить ошибки платформы до пользователя.

## 6. Структура репозитория (целевая)

```
gui/                  # общий PySide6-слой (перенесён из Linux-GUI)
  app/
    ui/…              # вкладки (status/config/update/help/…)
    theme.py, tray.py, window.py
    backend.py        # интерфейс Backend
    win_backend.py    # обёртка над пакетом Flowseal (winws+WinDivert)
    mock_backend.py   # заглушка для разработки на Linux
engine/               # распакованный пакет Flowseal (не в git, качается):
                      #   *.bat стратегии, lists/, bin/ (winws.exe, WinDivert, шаблоны)
service/              # планировщик задач / автозапуск helpers
build/                # PyInstaller spec, .github/workflows
```

## 7. Вехи (milestones)

- **M0 — план и репозиторий** (сейчас).
- **M1 — спайк бэкенда (Windows):** парсинг Flowseal .bat, поднятие
  WinDivert, запуск/остановка winws, `state()`. Проверяется вручную на
  Windows из консоли Python.
- **M2 — минимальный GUI на Windows:** Статус (запуск/остановка/состояние) +
  Способ обхода (с описанием) + Обновление (winws/стратегии) + трей. Работает
  из исходников (`python -m gui.app.main`), запуск от админа.
- **M3 — завершение концепта:** мастер первого запуска, автозапуск через
  планировщик, самопроверка, справка, тёмная тема полностью, UAC-поведение.
- **M4 — сборка/дистрибуция:** PyInstaller в `.exe`, проверка «на чистой»
  Windows, релизы с архивами, Actions-windows для сборки.

## 8. Открытые вопросы и решения (M0)

1. ~~Какие именно стратегии~~ → **Решено: нативные Flowseal `.bat`** (winws-стиль,
   имена «general (ALT).bat»). Парсер описаний адаптировать под их формат и проверить.
2. Источник ядра winws: bol-van/zapret релизы или Flowseal-пакет → **сравнить в M1**.
3. WinDivert: модель установки → **рекомендация от исследования (см. §9), проверить в M1**.
4. ~~Автозапуск~~ → **Решено: планировщик задач** (запуск при входе пользователя).
   Windows-сервис — возможная опция позже.
5. Обновление программы: самообновление архивом или через git (для dev).
6. ~~Модель UAC~~ → **Решено: всегда от администратора**
   (манифест `requireAdministrator`, как у Flowseal).

## 9. WinDivert — что выяснили (M0)

Изучены исходники и доки bol-van/zapret (`docs/windows*.md`, `nfq/`).

- winws работает поверх **WinDivert**: драйвер `WinDivert64.sys` + `WinDivert.dll`.
  Драйвер подписан (Secure Boot отключать не нужно на современных версиях).
- **winws, запущенный от администратора, сам поднимает драйвер** через WinDivert.dll
  при старте (в DLL есть автозапуск драйвера; в `nfq/darkmagic.c` отмечена лишь гонка
  при старте). Отдельная «установка» драйвера при обычном сценарии **не требуется** —
  достаточно админ-прав у процесса.
- Автозапуск winws штатно: **планировщик задач** (`task_*.cmd`) или **windows-сервис**
  (`service_*.cmd`); всё от админа.

**Вывод для GUI:**
- Раз GUI всегда работает от админа, отдельный шаг «установки драйвера» в мастере не нужен —
  драйвер поднимется сам при запуске winws.
- Предусмотреть запасную кнопку «Проверить/переустановить драйвер WinDivert»
  (создать службу драйвера: `sc create WinDivert type= kernel …`), если авто-подъём
  не сработает. Точную команду и необходимость подтвердить в M1 на реальной Windows.
